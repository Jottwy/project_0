## NO tocar
- Modelo de datos Rust (celdas 2.5 m): la conversión celda→tile vive SOLO en Unity (tileX = cellX / 2).
- **Clases nativas de STP/PolymindGames — nunca editarlas directamente** (hallazgo 2026-07-01, durante ADR-025 Slice A). Restricción dura de Unity: `PolymindGames.asmdef` NO puede referenciar `Assembly-CSharp` (donde vive `_Migration/STPIntegration/`, sin asmdef propio) — un asmdef explícito no puede depender del assembly implícito por defecto. Esto significa que si una clase STP necesitara consumir una señal externa, la clase-puente tendría que vivir físicamente DENTRO del árbol de `Assets/PolymindGames/` para ser visible — el mecanismo tentador siempre va a "vivir dentro de PolymindGames" aunque sea código nuevo nuestro. **La regla no es "evitar esa carpeta", es evitar la necesidad**: cualquier interacción con STP debe ser un interceptor/wrapper EXTERNO que actúa DESPUÉS de que STP hace lo suyo (ej. `AuthoritativePoseApplier` deja que `SoloSurvivalGameMode.SetPlayerPosition` haga su teletransporte local nativo, y lo corrige un instante después vía la pose autoritativa) — nunca un guard/edit dentro del método STP, y nunca una clase-señal nueva colocada dentro de `Assets/PolymindGames/` para que STP la lea. Caso de estudio revertido: un guard `PlayerRespawnGate.RepositionLocally()` se añadió dentro de `SoloSurvivalGameMode.OnPlayerRespawn` + una clase gate nueva en `Assets/PolymindGames/FPSCore/Code/Runtime/Core/` — ambos revertidos; `AuthoritativePoseApplier` solo (sin tocar STP) cubre el mismo caso.
